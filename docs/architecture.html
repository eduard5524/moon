Architecture

Moon uses a multi-agent architecture where a central Planner decomposes tasks and distributes them to specialized agents through a prioritized task queue.

The Planner

The Planner is the brain of Moon. It receives high-level task descriptions and breaks them down into concrete, executable steps.

Responsibilities

  • Task Decomposition — Breaks complex tasks into atomic subtasks
  • Strategy Selection — Chooses the best approach based on context
  • Progress Monitoring — Tracks execution and adjusts plans dynamically
  • Error Recovery — Detects failures and creates recovery plans
  • Human Escalation — Identifies when to ask for approval or clarification

Planning Process

# Example: Planner decomposition for "Add user authentication"

Task: Add user authentication
├── 1. Analyze existing codebase structure
│   ├── Identify framework (Express, FastAPI, etc.)
│   ├── Check existing auth patterns
│   └── Review database schema
├── 2. Design authentication flow
│   ├── Choose strategy (JWT, session, OAuth)
│   ├── Define API endpoints
│   └── Plan database migrations
├── 3. Implement (Coding Agent)
│   ├── Create auth middleware
│   ├── Add login/register endpoints
│   ├── Create user model/migration
│   └── Add password hashing
├── 4. Test (Testing Agent)
│   ├── Unit tests for auth logic
│   ├── Integration tests for endpoints
│   └── Security tests (SQL injection, XSS)
├── 5. Document (Documentation Agent)
│   ├── API documentation
│   ├── Auth flow diagram
│   └── Setup instructions
└── 6. Deploy (Deployment Agent)
    ├── Update environment variables
    ├── Run database migrations
    └── Deploy to staging

Task Queue

The Task Queue manages the execution order of subtasks, handles dependencies, and enables parallel execution where possible.

Features

Feature Description
Priority Scheduling Critical-path tasks execute first
Dependency Graph Tasks wait for prerequisites to complete
Parallel Execution Independent tasks run simultaneously
Retry Logic Failed tasks retry with exponential backoff
Deadlock Detection Circular dependencies are identified and resolved

Memory System

Moon maintains both short-term and long-term memory to preserve context across tasks and sessions.

Memory Types

  • Working Memory — Current task context, recent actions, active file contents
  • Episodic Memory — Past task executions, what worked and what didn't
  • Semantic Memory — Project knowledge, code patterns, architecture decisions
  • Procedural Memory — Learned workflows, common fix patterns, deployment procedures

Execution Sandbox

All code execution happens inside isolated Docker containers, ensuring safety and reproducibility.

Sandbox Features

  • Isolation — Each task runs in its own container
  • Reproducibility — Deterministic environment setup
  • Resource Limits — CPU, memory, and disk quotas
  • Network Controls — Whitelisted external access
  • Snapshots — Save and restore execution state

Error Handling

Moon handles errors at multiple levels:

  1. Agent Level — Individual agents retry failed operations
  2. Task Level — Failed tasks are re-queued with adjusted parameters
  3. Plan Level — The Planner revises the strategy when approaches fail
  4. System Level — Critical failures trigger human escalation
